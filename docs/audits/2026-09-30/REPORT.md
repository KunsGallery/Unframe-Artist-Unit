# U.A.U 전체 페이지 UX·구현 점검

검사일: 2026-09-30. 대상: 운영 사이트 https://uau.unframe.kr 및 현재 로컬 코드. Product Design 감사 방식에 따라 실제 화면을 먼저 확인하고 관련 구현을 대조했습니다.

## 결론

아이보리·블루·에디토리얼 타이포그래피라는 브랜드 방향은 유지할 가치가 있습니다. 지금은 새 기능을 늘리기보다 **이미 안내하고 있는 기능을 실제 동작과 일치시키고, 모바일 작가 페이지와 입력·저장 동선을 안정화하는 작업**이 우선입니다.

이 문서는 진단 결과입니다. 앱 코드, 운영 데이터, 권한, 발행 상태는 수정하지 않았으며 커밋·푸시·배포하지 않았습니다.

## 검사 범위와 한계

- 실제 브라우저: 공개 메인·목록·연결·Radar·리캡·소개·가입 안내, 로그인 화면, 회원 대시보드, 프로필, 성장·해금, 공개 페이지 안내, 문의함, 프라이빗 뷰잉룸, 추천, 알림, 스레드, 기획 브리프, 관리자 개요·승인·작가 관리·기관 관리·사이트 편집기.
- 작가 상세와 동일 편집 화면: 관리자가 미리볼 수 있는 기존 비공개 `jaewoo-kim` 프로필로 검사. 예시 데이터는 생성하지 않았습니다.
- 데스크톱 1440×900, 모바일 390×844 뷰포트 설정. 캡처의 콘텐츠 폭은 브라우저 스크롤바 등으로 조금 다릅니다. 검사 후 뷰포트 설정을 복원했습니다.
- 계정은 슈퍼관리자이며 현재 회원 역할은 컬렉터입니다. 별도 일반 작가·큐레이터 계정으로 권한을 재검증한 것은 아닙니다.
- 검사 당시 공개 아티스트·작품·갤러리·전시 목록이 비어 있었습니다. 따라서 실제 공개 작품의 상세 모달, 문의 전송 성공, 전시 상세, 랜덤 작가 이동, 데이터가 많은 목록의 성능은 검증하지 못했습니다.
- 저장·발행·업로드·승인·역할 전환·테스트 초기화는 실행하지 않았습니다. 저장 문제는 코드상 위험과 실제 재현 결과를 분리했습니다.
- 로딩 직후 일부 캡처는 잠정 상태였습니다. 확정 증거로는 아래 지정된 캡처를 사용하고, 초기 로딩/폭이 비정상인 캡처는 판단 근거에서 제외합니다.
- Lighthouse·실기기·스크린리더·네트워크 단절 테스트, 빌드 및 전체 권한 테스트는 이번 읽기 전용 점검에 포함하지 않았습니다.

## 1. 먼저 수정할 사항

### P1-01. 모바일 작가 상세의 이름 영역이 붕괴함 — 브라우저 재현

경로: `/artist/jaewoo-kim`.

390px 환경에서 커버와 이름이 두 열로 남고 이름 열이 약 **47px**까지 좁아졌습니다. `Jaewoo Kim`이 여러 글자 단위로 세로로 끊겨 작가의 정체성을 전달하지 못합니다. DOM에서 히어로 그리드는 `270px 47px`로 확인됐습니다. 로딩 후 다시 방문해 동일하게 재현했습니다.

개선: 모바일에서는 커버와 이름을 완전히 한 열로 배치하고, 페이지별 디자인 설정이 반응형 규칙을 덮어쓰지 못하도록 제한합니다. 긴 영문 이름·긴 한글 이름·커버 없음·커버 있음·세 템플릿을 함께 검사해야 합니다. 로컬 CSS에는 이미 모바일 1열 규칙이 있어, 운영 적용 스타일과 우선순위까지 확인해야 합니다.

완료 기준: 360/390/430px에서 이름이 정상적인 단어 단위로 읽히고 커버가 텍스트를 밀어내지 않음.

증거: [모바일 작가 페이지](31-artist-mobile-settled.jpg), [데스크톱 작가 페이지](27-artist-draft.jpg).

### P1-02. 사이트 편집기 섹션 제어와 실제 홈페이지 구조가 다름 — 화면 + 코드

경로: `/admin/editor`, `/`.

편집기에는 Radar·현재 연결·연간 리캡·셀렉션·저널 등이 홈 섹션으로 표시됩니다. 실제 홈페이지는 선언 띠·소개·공간 아카이브·아티스트·작품·FAQ·참여 구조입니다. 현재 `app/page.tsx`는 편집기의 섹션 순서/숨김을 적용하는 `PageSection`을 사용하지 않습니다. 따라서 직원이 제어를 바꿔도 의도한 홈 구조를 바꾸지 못할 위험이 확실합니다. 발행 자체는 실행하지 않았습니다.

개선: 실제 홈 섹션을 단일 스키마로 정의하고 렌더러와 편집기가 같은 목록·ID·순서·가시성을 사용하도록 통합합니다. 편집 불가능한 문구는 구분해서 표시해야 합니다.

완료 기준: 각 실제 섹션을 숨기고 순서를 바꾸면 미리보기·발행 후 새 창·새로고침에서 같은 결과가 유지됨. 검증은 별도 테스트 환경에서 수행.

코드: `app/page.tsx`, `app/admin/editor/page.tsx:398`, `app/site-pages.ts`.

### P1-03. 상세 편집 미리보기가 삭제된 데모 주소에 고정됨 — 브라우저 재현

작가 상세를 선택하면 `/artist/seo-yujin`이 열려 “아직 열리지 않은 공간입니다”가 표시됩니다. 실제 수정할 작가를 보고 있는 것이 아닙니다. 작품 상세 `/works/the-distance-between`, 프로젝트 상세 `/projects/after-the-salon`도 코드에 고정되어 있습니다. 후자 두 주소는 코드상 문제이며 이번 브라우저에서 개별 확인하지 않았습니다.

개선: 실제 작가·작품·프로젝트 선택기를 제공하고, 대상이 없으면 “등록 후 편집할 수 있습니다”와 등록 이동 버튼을 표시합니다. 해당 상세에서 적용되지 않는 공통 홈 제어는 숨깁니다.

증거: [작가 상세 편집 미리보기](33-editor-detail.jpg). 코드: `app/site-pages.ts:15`, `:17`, `:19`.

### P1-04. 프라이빗 뷰잉룸에 권한 오류가 표시됨 — 브라우저 재현

경로: `/dashboard/viewing-room`.

현재 슈퍼관리자 세션에서도 `Missing or insufficient permissions.`가 표시됩니다. 다른 관리자 페이지는 접근되므로 단순 미로그인 상태로 설명할 수 없습니다. 조회 단계의 오류이며 생성·저장을 시도한 것은 아닙니다. 로컬 규칙은 소유자 또는 관리자 목록 읽기를 허용하므로, 운영에 배포된 규칙·관리자 판정·실제 쿼리를 대조해야 합니다. 원인을 특정 규칙 하나로 단정하지 않습니다.

개선: 권한 실패 때 입력 폼을 정상 상태처럼 보여주지 말고 한국어 안내·재시도·문의 경로를 제공합니다. 소유자·관리자·초대 링크 방문자의 읽기/쓰기 테스트를 자동화합니다.

증거: [권한 오류 화면](35-viewing-permissions.jpg). 코드: `app/dashboard/viewing-room/page.tsx:35`, `firestore.rules:356`.

### P1-05. 버추얼 갤러리 이용 안내와 운영 기능이 연결되지 않음 — 화면 + 코드

프로필에는 “AI 공간 프리뷰”, “멤버십 또는 인증을 받으면 전체 버츄얼 갤러리가 열립니다”라고 안내합니다. 하지만 `/dashboard/virtual-gallery`는 공개 페이지·해금 안내 위주이고, 실제 3D 편집기 링크는 개발 환경에서만 `127.0.0.1:5174`로 연결됩니다. 로컬 3D 프로토타입과 운영 홈페이지가 별개입니다.

개선: 통합 전에는 “준비 중 / 로컬 테스트”로 정확히 안내합니다. 통합 시 작가 소유권·전시 저장·미디어 접근·공개 링크·해금 적용을 한 흐름으로 연결해야 합니다. 이는 문구 변경보다 큰 작업입니다.

증거: [공개 페이지·해금 안내](17-virtual-gallery.jpg), [프로필 모바일 전체](29-profile-mobile.jpg). 코드: `app/dashboard/virtual-gallery/page.tsx`, `prototypes/virtual-gallery/AGENTS.md`.

### P1-06. 관리자 신규 작가 저장의 undefined 값 위험 — 코드상 확인, 저장 미실행

`app/admin/artists/page.tsx:31`의 초기값에 `verificationStatus: undefined`가 있고, 저장 시 폼을 그대로 펼쳐 `setDoc`에 전달합니다. 현재 Firebase 클라이언트는 `ignoreUndefinedProperties`를 켜지 않습니다. 신규 등록 흐름에서 undefined 필드 때문에 쓰기가 거절될 수 있습니다. 기존 작가 편집 화면은 별도 흐름이므로 구분해야 합니다.

개선: 저장 페이로드를 명시적으로 구성하고 undefined를 제거하거나 유효한 상태값을 사용합니다. 관리자 생성 프로필의 소유자 지정·실제 작가 계정 인계도 함께 명확히 합니다.

완료 기준: 테스트 환경에서 신규 초안 등록→편집→공개→작가에게 인계까지 검증.

## 2. UX와 운영 흐름 개선

### P2-01. 프로필 편집이 너무 길고 저장 위치가 불편함

모바일 프로필 캡처는 수천 픽셀 길이입니다. 대표작·아카이브·영감·문의 설정은 저장 버튼 아래에 있어 아래쪽을 편집한 뒤 위로 돌아가야 합니다. 페이지 미리보기는 현재 입력 초안이 아니라 저장된 페이지를 보는 경로입니다.

개선: `기본 소개 / 작품 / CV / 페이지 디자인 / 연락·미디어` 탭 또는 단계형 구성을 사용합니다. 하단 고정 저장바, 저장되지 않음 표시, 이탈 경고, 초안 미리보기, 선택적인 자동 초안 저장이 필요합니다. 작가의 첫 등록에서는 필수 3단계만 먼저 보여줍니다.

증거: [프로필 모바일](29-profile-mobile.jpg). 관련 코드: `app/dashboard/profile/page.tsx`.

### P2-02. 컬렉터에게 작가용 입력·해금·도구가 그대로 나타남

실제 컬렉터 계정에 작가노트·작가 이력·공개 페이지 빌더·대표작 입력과 성장·해금 메뉴가 표시됩니다. 기획 브리프는 클릭 후에야 권한 안내가 나옵니다. 권한이 없는 기능을 먼저 노출하면 기능이 고장 났다고 느낄 수 있습니다.

개선: 역할에 맞는 기본 대시보드와 프로필을 제공하고, 다른 역할은 “역할 추가 신청”으로 연결합니다. 슈퍼관리자 테스트 권한과 일반 회원 이용 가능 상태를 따로 표시합니다.

증거: [프로필 모바일](29-profile-mobile.jpg), [성장과 해금](18-progress.jpg). 코드: `app/dashboard/dashboard-sidebar.tsx`, `app/dashboard/profile/page.tsx`.

### P2-03. 비어 있는 공개 페이지 사이에서 방문자가 순환함

메인에서 아티스트→작품→연결→프로젝트를 따라가도 대부분 빈 목록입니다. 아티스트 0명인데 랜덤 버튼이 있고, 검색하지 않았는데 “다른 이름이나 분야로 검색”을 권합니다. 작품 목록의 “공개 아카이브” 링크는 `#`입니다.

개선: `처음 등록 준비 / 검색 결과 없음 / 로딩 / 조회 실패`를 구분합니다. 전체 데이터가 없을 때 랜덤 버튼은 숨기고, 실제 등록·소개·다음 업데이트 안내로 연결합니다. 관리자에게는 빈 목록 안에 등록 바로가기를 제공합니다. 더미를 공개 콘텐츠로 다시 넣을 필요는 없습니다.

증거: [아티스트 목록](02-artists.jpg), [작품 목록](07-works.jpg), [연결](10-connections.jpg), [메인 모바일](28-home-mobile.jpg).

### P2-04. 관리자 화면의 시각적 위계가 업무와 맞지 않음

승인 화면·관리자 개요에서 대형 슬로건과 여백이 실제 대기열·업무 제어보다 많은 공간을 차지합니다. 알림 전송이나 권한 관리에는 UID 입력 등 기술적인 표현이 노출됩니다. 운영 직원에게는 등록·심사·편집·알림이 작업 중심으로 묶여야 합니다.

개선: 상단은 작은 제목·요약 숫자·등록 버튼으로 압축하고, `승인 대기 / 작가 / 갤러리·전시 / 사이트 편집 / 알림`을 지속적인 관리자 내비게이션으로 제공합니다. UID 대신 이름·이메일 검색을 사용합니다. 라이브 계정 상태를 바꾸는 테스트 초기화/역할 전환은 별도 테스트 영역과 명확한 경고로 분리합니다.

증거: [관리자 개요](03-admin.jpg), [승인](25-access.jpg).

### P2-05. 작가 페이지에 플랫폼 내비게이션이 중복됨

전역 헤더와 작가 미니사이트 헤더가 함께 나타나고, 하단도 작가 푸터와 플랫폼 푸터가 이어집니다. 모바일에서는 빠른 이동 독과 `?` 도움 버튼이 겹칩니다. 작은 개인 사이트보다 여러 화면이 겹친 인상이 강합니다.

개선: 작가 페이지 전용 셸로 플랫폼 복귀와 작가 내부 탐색을 한 헤더에 묶습니다. 하단 독과 도움 버튼의 안전영역을 분리합니다. 빈 전시·CV 섹션은 축약하고 공개 전 완성도 안내는 관리자 미리보기 안에서만 자세히 제공합니다.

증거: [작가 데스크톱](27-artist-draft.jpg), [작가 모바일](31-artist-mobile-settled.jpg). 코드: `app/layout.tsx`, `app/public-artist-page.tsx`.

### P2-06. 입력 UI의 언어·접근성 일관성이 부족함

한국어 화면의 이미지 업로더에 `Choose an image`, 오류 영문, `Remove`가 남습니다. 이미지가 이미 있을 때 교체 버튼은 접근성 이름이 비어 있습니다. 추천 알림 주기도 `realtime / weekly / monthly / off`로 그대로 노출됩니다. 작은 보조글과 일부 아이콘 버튼은 모바일에서 읽고 누르기 어렵습니다.

개선: 모든 공용 업로더·오류·선택지를 번역하고 교체 버튼에 파일 용도별 이름을 부여합니다. 최소 터치 영역과 본문/보조글 크기를 통일합니다. 실제 예약 전송이 없는 알림 설정은 “선호 저장”과 구분해 안내합니다.

코드: `app/components/r2-image-uploader.tsx`, `app/dashboard/recommendations/page.tsx`. 증거: [프로필 모바일](29-profile-mobile.jpg), [추천](21-recommendations.jpg).

### P2-07. 가입 동선과 기존 회원 재진입이 불명확함

`/join`과 `/enter`에 각각 역할 안내가 있고, 일부는 로그인, 일부는 이메일 문의로 연결됩니다. 이미 로그인한 상태에서도 `/login`에 로그인 폼이 보입니다. 로그인 폼에 비밀번호 재설정 경로가 보이지 않습니다. 준비 중인 소셜 로그인 세 종류가 실제 사용 가능한 선택지를 밀어냅니다.

개선: 가입과 기존 회원 역할 추가를 구분하고, 하나의 진입 흐름으로 통합합니다. 비밀번호 재설정 경로를 추가하고 사용 가능한 로그인 방식부터 보여줍니다.

증거: [로그인](36-login.jpg), [역할 진입](37-enter.jpg), [함께하기](13-join.jpg).

## 3. 코드·성능·콘텐츠 확장

### P2. 원본 업로드와 표시용 이미지를 분리

업로더는 최대 50MB 이미지 파일을 허용하고 그대로 R2로 전송합니다. 공개 작가 페이지의 이미지는 일반 `img`와 같은 URL을 이용하며 반응형 파생 이미지 선택이 충분하지 않습니다. 지연 로딩은 일부 이미 이미 적용돼 있으므로 “없다”고 볼 수 없습니다.

개선: 원본 보존 + 작은 썸네일 + 목록용 + 상세용 파생 이미지를 만들고 `srcset/sizes`를 사용합니다. 원본은 상세 확대 시에만 요청합니다. 업로드 단계에서 크기/방향/포맷을 검증합니다. 일괄 파일 변환으로 원본을 덮어쓰지 않습니다.

### P2. 공개 목록 쿼리의 페이지네이션과 정렬

공개 프로필을 모두 구독하고 그 안의 작품을 펼쳐 사용하는 코드가 있습니다. 데이터가 늘면 목록에서 불필요한 필드까지 받게 됩니다. “새롭게 연결된” 아티스트는 최신순 정렬 없이 일부를 자르고, 랜덤은 최대 100개 후보에서 선택합니다.

개선: 목록용 요약 데이터와 상세 데이터를 분리하고 공개일 기준 정렬·커서 페이지네이션을 적용합니다. 빈 결과와 쿼리 실패를 구분하고, 홈/목록의 중복 구독을 줄입니다.

코드: `app/components/newly-connected.tsx`, `app/components/random-artist-link.tsx`, `app/live-works.ts`, `app/organizations.ts`.

### P2. 공유 미리보기와 검색 노출

루트 메타데이터는 플랫폼 공통값이고, 조사한 작가·작품·갤러리 상세 경로에서 개별 `generateMetadata`가 확인되지 않았습니다. 작가가 링크를 공유할 때 작가명·대표작 이미지가 보이도록 개선할 가치가 큽니다.

개선: 공개 상세의 서버 메타데이터·OG 이미지·정규 URL을 제공하고, 비공개 페이지는 검색 노출에서 제외합니다. 실제 소셜 미리보기는 이후 별도 검증합니다.

### P2. 프라이빗 뷰잉룸의 보호 수준을 정확히 정의

현재는 비밀번호나 로그인 초대 기반이 아니라 문서 ID 링크를 아는 사람이 접근하는 방식입니다. 이미지도 공개 R2 URL입니다. 화면에 제한사항이 안내되어 있는 점은 좋습니다. 다만 미공개 신작을 안전하게 보관하는 서비스로 홍보하면 기대와 다릅니다.

개선: `비공개 링크 전시`라는 명칭을 사용하거나, 실제 보호가 필요하면 비공개 버킷·짧은 만료 서명 URL·초대 만료/철회·접근 로그를 구현합니다. 링크를 닫아도 이미 복사한 공개 이미지 URL까지 철회되는 구조는 아닙니다.

### P3. 리캡·오픈콜 콘텐츠를 실제 관리 데이터로 연결

리캡은 정적인 빈 `annualRecap`에 의존하고 Radar의 오픈콜은 빈 상태 안내로 남습니다. 실제 운영 정보가 생겨도 화면이 자동으로 채워지는 경로가 부족합니다.

개선: 실제 입력·발행 관리가 준비되기 전 메뉴 노출을 줄이고, 이후 전시/활동 집계와 오픈콜 관리 데이터를 연결합니다.

### 성능에 관한 기존 가정 정정

로컬 디렉터리 크기 확인: `public` 약 864KB, 로컬 3D 프로토타입 `public` 약 19MB, `.next` 약 455MB, `node_modules` 약 574MB. 개발 의존성과 전체 빌드 파일 크기는 한 페이지의 네트워크 전송량이 아닙니다. 따라서 “프로젝트가 1GB이므로 방문자가 1GB를 내려받는다”는 결론은 타당하지 않습니다. 운영 R2 원본 이미지·실제 JS 청크·폰트 전송량·LCP/INP는 별도 실측해야 합니다.

## 5. 추천 개선 순서와 완료 판정

1. **기능 신뢰성**: 모바일 작가 히어로, 뷰잉룸 권한, 신규 작가 저장, 잘못된 상세 미리보기. 운영 데이터 없이 테스트 환경에서 재현/수정.
2. **직원 편집 경험**: 실제 홈 스키마 통합, 탭별 입력·고정 저장바·이탈 경고, 저장 전 미리보기, 발행 후 새 세션 확인.
3. **방문자 경험**: 빈 섹션 압축, 목록의 제목/여백 정리, 작가 전용 셸과 모바일 독 안전영역, 가입 동선 통합.
4. **확장 기반**: 이미지 파생본·목록 쿼리·개별 OG, 오류 상태와 한국어 접근성 마감.
5. **버추얼 운영 통합**: 소유자·전시 저장·공개 공유·해금 적용을 연결한 뒤 이용 가능 문구와 멤버십 안내 확정.

회귀 검사에는 일반 작가/관리자/비회원, 초안/공개/비공개, 데이터 0/1/다수, 모바일/데스크톱, 한국어/영어, 정상/권한 거절/네트워크 실패를 포함해야 합니다. 스크린샷뿐 아니라 저장→새로고침→새 세션의 데이터 일치와 실제 역할별 권한도 완료 기준으로 삼습니다.

디자인 원칙: 브랜드 소개 페이지에는 큰 타이포그래피를 남기되, **목록은 탐색, 관리자 화면은 업무, 작가 페이지는 작품**이 가장 먼저 보이도록 화면별 밀도를 다르게 설계합니다.
