# 직원 계정 확인 체크리스트

운영 반영: 2026-09-23 · Firebase 프로젝트: `unframe-uau`

이 문서는 오늘 직원이 실제 계정으로 화면과 데이터 흐름을 점검할 때 사용합니다. 이미 Firestore 보안 규칙은 배포되었고, 자동 권한 검사는 로컬 전용 demo 프로젝트에서 통과했습니다. 운영 데이터는 수정하거나 삭제하지 않았습니다.

## 시작 전

- [ ] 직원용 일반 계정과 관리자 계정으로 각각 로그인할 수 있는지 확인합니다.
- [ ] 프로필에 표시될 이름, 활동 지역, 소개, 공개할 작품 이미지와 전시 기록을 준비합니다.
- [ ] 갤러리 대표 계정에서 관리할 갤러리 이름, 도시, 웹사이트를 확인합니다.
- [ ] 테스트에 쓸 두 번째 계정(작품 문의 발신자)을 준비합니다.
- [ ] 실제 공개해도 되는 기록만 발행합니다. 확인되지 않은 전시나 참여 작가는 초안으로 둡니다.

## 1. 가입·역할 승인

- [ ] 새 일반 계정으로 로그인한 뒤 프로필 문서가 만들어지고 승인 대기 문구가 없는지 확인합니다.
- [ ] 갤러리·큐레이터 역할 신청은 `/admin`의 **승인 신청**에 표시되는지 확인합니다.
- [ ] 승인 전에는 신청 계정이 승인 전용 기획 브리프를 만들 수 없는지 확인합니다.
- [ ] 관리자 계정으로 신청을 승인한 뒤, 신청자가 다시 로그인하거나 새로고침했을 때 해당 기능을 사용할 수 있는지 확인합니다.
- [ ] 일반 직원 계정에서 관리자 권한을 추가할 수 없고, 관리자 목록은 슈퍼 어드민만 관리할 수 있는지 확인합니다.

## 2. 프로필·작품 공개 흐름

- [ ] `/dashboard/profile`에서 이름과 소개를 수정하고 저장합니다.
- [ ] 공개 주소가 다른 사람의 주소와 충돌하면 저장이 거부되는지 확인합니다.
- [ ] 기존 계정의 공개 주소를 변경할 경우, 새 주소가 열리고 이전 주소가 더 이상 계정 소유권을 가리키지 않는지 확인합니다.
- [ ] 작품 제목·연도·매체를 입력하고 실제 이미지 파일을 업로드합니다.
- [ ] 프로필 공개 설정 후 작품이 홈, `/works`, 작품 상세 화면에 같은 제목과 이미지로 나타나는지 확인합니다.
- [ ] 미공개 프로필과 비공개 작품이 로그아웃 상태에서 보이지 않는지 확인합니다.

## 3. 사이트 편집기

- [ ] `/admin/editor`에서 페이지를 선택하고 미리보기의 본문을 직접 수정합니다.
- [ ] 줄바꿈을 넣고 한국어·영어 화면에서 저장 전 미리보기가 같은지 확인합니다.
- [ ] 이미지 교체, 데스크톱·태블릿·모바일 미리보기를 각각 확인합니다.
- [ ] 저장하지 않은 상태에서 새로고침 후 이 기기의 임시 초안이 복구되는지 확인합니다.
- [ ] 페이지 이동 후 다시 돌아와 임시 편집 내용이 남아 있는지 확인합니다.
- [ ] 변경사항 발행 후 새 브라우저 탭에서 실제 공개 페이지에 반영됐는지 확인합니다.
- [ ] 버전 목록에서 이전 버전을 선택해 복원하고 다시 발행할 수 있는지 확인합니다.

## 4. 갤러리·전시·Radar·관계

- [ ] `/admin/organizations`에서 언프레임 갤러리와 쿤스갤러리를 각각 별도 갤러리 기록으로 등록하거나 기존 기록을 선택합니다.
- [ ] 소개, 도시, 웹사이트를 확인하고 갤러리 페이지를 공개합니다.
- [ ] 각 갤러리에 전시를 만들고 시작일·종료일과 공개된 아티스트 프로필을 연결합니다.
- [ ] 전시 날짜가 역전된 경우 저장이 막히는지 확인합니다.
- [ ] 실제 공개 전시가 `/projects` 목록과 전시 상세에 표시되는지 확인합니다.
- [ ] 날짜가 있는 공개 전시만 `/radar`의 일정에 나타나는지 확인합니다.
- [ ] `/connections`의 관계 지도와 텍스트 목록에 해당 전시·갤러리·작가 연결이 함께 표시되는지 확인합니다.
- [ ] 참여가 확인되지 않은 아티스트는 전시 초안에 두고, 공개 관계에 나타나지 않는지 확인합니다.

## 5. 작품 문의·받은 편지함·추천

- [ ] 두 번째 로그인 계정으로 공개 작품 상세에 들어가 10자 이상의 문의를 보냅니다.
- [ ] 작품 소유 계정의 `/dashboard/inquiries`에 문의가 도착하는지 확인합니다.
- [ ] 문의 상태를 진행 중·답변 완료·종료로 바꾸고 새로고침 뒤 유지되는지 확인합니다.
- [ ] 문의 발신자와 작품명이 정확한지 확인하고, 이메일 링크가 올바른 주소를 여는지 확인합니다.
- [ ] `/dashboard/recommendations`에서 본인 관심사와 일치하는 이유가 표시되는지 확인합니다.
- [ ] 관심사나 공개 작품이 없을 때 실제 자료가 없는 빈 상태가 보이고 가짜 추천은 나오지 않는지 확인합니다.

## 데이터 정리 원칙

- 이 배포와 권한 테스트는 운영 Firestore 문서, 계정, R2 파일을 삭제하지 않았습니다.
- 에뮬레이터 테스트의 임시 문서는 `demo-uau-rules-tests`라는 로컬 전용 프로젝트에만 생성되고 테스트 종료 시 비워집니다.
- 코드의 고정 샘플 목록은 실제 Firestore 조회로 교체했고, 준비되지 않은 작품·전시·모집은 빈 상태로 표시합니다. `/assets/uau-hero.webp` 같은 브랜드 그래픽은 샘플 작가 데이터가 아니므로 삭제 대상이 아닙니다.
- 운영 Firestore나 R2에 이미 있는 샘플 계정·문서를 지울 계획이라면 먼저 문서 ID, 소유자, 연관 이미지·전시·작품과 복구 방법을 확인해야 합니다. 이번 작업에서는 운영 샘플 데이터의 삭제 대상을 조사하거나 삭제하지 않았습니다.
